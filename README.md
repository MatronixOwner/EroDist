# EroDist 0.9 — Linux Mint Cinnamon

Тестовая производная **Linux Mint 22.3 Cinnamon x86_64**. Создатель: **d50130483-ship-it**.
Сохраняются пакетная база, обновления, драйверы, Cinnamon и дисковый backend Mint. Это не официальный выпуск Linux Mint.

## Редакции: выбор только во время установки

| Редакция | Состав |
|---|---|
| **Home** | Стандартные приложения Mint для браузера, видео, соцсетей и офисной работы. Дополнительных загрузок редакции нет. |
| **Pro** | Home + Steam, GameMode, MangoHud, Mesa/Vulkan и 32-битные библиотеки. Требуются интернет, официальные репозитории Ubuntu universe/multiverse и явное принятие условий Valve. Игры и Proton загружаются отдельно; Steam может обновить клиент при первом запуске. |
| **Program** | Home + Git, Python/pip/venv/Tk, C/C++, Clang, CMake, Ninja, GDB, Node.js/npm, Geany, **Godot 3**, Blender. Тёмный профиль GNOME Terminal. Нужен интернет. Unity/Unreal и Steam автоматически не устанавливаются. |

Рекомендуемый виртуальный диск: Home от 30 ГиБ, Pro от 60 ГиБ, Program от 70 ГиБ; игры и проекты требуют отдельного запаса. Это не гарантированный расчёт всех зависимостей. Перед загрузкой проверяется свободное место; пакетные ошибки не скрываются.

## Что изменено

- Два зарегистрированных Debian-пакета: `erodist-system` и live-only `erodist-installer`, а не только обои и переименование.
- Встроенная страница Home / Pro / Program **в мастере Ubiquity перед выбором диска**. Изначально редакция не выбрана; Pro недоступна без согласия с условиями Valve.
- Своя тёмная страница с округлёнными карточками и кнопками. **Разметка, экран дисков и загрузчик остаются штатными Mint**, не полностью переписанным Windows-подобным установщиком. Полное визуальное переоформление остальных страниц не заявляется.
- «Центр настроек EroDist»: оформление, устройства, пакеты, сеть и раздел «О системе» с версией, редакцией, создателем и локальными сведениями об оборудовании. Подразделы открывают совместимые штатные модули Mint/Cinnamon. Переключателя редакций после установки нет.
- Чёрный градиент, Mint-Y-Dark; без телефонной интеграции, отдельного поиска и старых EroDist-приложений.
- Состояния установки `installing` / `failed` / `complete` в `/var/lib/erodist/installation.json`. При ошибке установки пакетов — ненулевой результат шага Ubiquity; система может остаться частично установленной, считать её готовой нельзя. Лог: `/var/log/installer/erodist-edition.log` на целевом диске.

Проприетарный драйвер GPU не ставится вслепую. Работа каждой игры, античита и ускорение Hyper-V не гарантируются. Не запускайте параллельно несколько экземпляров установщика.

## Сборка

Workflow `.github/workflows/iso.yml` проверяет подписанный оригинал Mint с закреплённым fingerprint, устанавливает `.deb` в squashfs, проверяет каталог пакетов, обновляет manifests и MD5, затем переносит оригинальные BIOS/UEFI-записи через `xorriso -boot_image any replay`.
Только `erodist-installer` добавляется в manifest удаления live-only пакетов; `erodist-system` остаётся в установленной ОС. Подпись Mint относится к **исходнику**, не подписывает изменённый EroDist ISO.

Локальные проверки:
```sh
python3 -m unittest discover -s tests -v
bash scripts/build-packages.sh
```

Полная сборка требует Linux/root, сети к зеркалам Mint/Ubuntu, xorriso, squashfs-tools, dconf-cli, gnupg, curl, xvfb, xauth и достаточного свободного места:
```sh
sudo bash scripts/build.sh
```

## Временная страница скачивания

`site/index.html` и `scripts/download-server.py` дают страницу с одной кнопкой и цельным ISO. Сервер слушает `0.0.0.0:8080`, поддерживает HTTP Range/докачку и не публикует файл до проверки размера и SHA256. Это временный сервер сессии, не постоянное зеркало.

Режим `workflow_dispatch` существующего ISO workflow с заполненными `upload_url` и одноразовым `upload_token` переносит **уже опубликованную 0.9**, не пересобирает дистрибутив. Передача идёт ограниченными порциями; после успешной проверки вход загрузки закрывается. Токен не коммитится и скрывается в логах Actions. Также перенос запускается push-коммитом с маркером `[publish-download]` и публичным адресом в `site/deploy.json`. В этом режиме сервер проверяет временный installation token Actions через GitHub API; секреты в исходниках не хранятся. Обычные push-коммиты по-прежнему собирают ISO.


**Результат проверки временного сайта:** интерфейс доступен в предпросмотре Arena, но внешний запрос из GitHub Actions получил `403 Missing traffic access token` на уровне среды. ISO **не перенесён**, рабочая прямая ссылка не заявляется. Это ограничение доступа среды, а не успешное развёртывание публичного зеркала. Для реальной раздачи цельного ISO нужен доступный извне сервер/хостинг; интерфейс и обработчик скачивания подготовлены. Проверки передачи в Actions завершились ошибкой, тогда как unit-тесты HTTP-сервера проходят.
