# EroDist — новый старт на Linux Mint Cinnamon

**0.8.0-mint1**, минимальная производная сборка **Linux Mint 22.3 Cinnamon, amd64**. Это не официальный образ Linux Mint и не обновление прежних Debian/Arch-установок. Старые ISO остаются в [Releases](https://github.com/d50130483-ship-it/EroDist/releases).

## Что внутри

Штатные Cinnamon, установщик, менеджер приложений и обновлений Linux Mint. Наша небольшая накладка: выбранные чёрные градиентные обои, тёмная тема Mint-Y и `/etc/erodist-version`. Идентификаторы Mint, пакеты, репозитории, учётные записи, загрузчики и установщик не переименовываются и не подменяются.

Archiso, pacman, Archinstall, прежний Calamares, самописный каталог и Wine-запускатель **удалены из новой сборки**. Сначала проверяем чистую основу, затем решаем, какие функции возвращать. Связь с телефоном и отдельный поиск не добавляем.

## Скачать

[Releases](https://github.com/d50130483-ship-it/EroDist/releases) · [Сборка](https://github.com/d50130483-ship-it/EroDist/actions/workflows/iso.yml)

Mint ISO больше лимита GitHub **2 ГиБ на один файл**, поэтому релиз содержит несколько частей `.iso.part01`, `.iso.part02` и т. д. **Отдельная часть не является загрузочным ISO.**

### Windows / Hyper-V

1. Скачайте **все** `.partNN` из одного релиза, `ASSEMBLY.json`, `assemble.ps1` и `assemble.cmd` в одну папку. Не смешивайте файлы разных релизов.
2. Запустите `assemble.cmd`. Он запускает соседний локальный PowerShell-скрипт; права администратора не нужны. Скрипты доступны для просмотра, ничего не скачивают и не записывают на диски/флешки.
3. Проверяются SHA256 каждой части и итогового ISO. При ошибке остановитесь и скачайте повреждённую часть заново. Уже существующий ISO не перезаписывается.
4. Подключите полученный `erodist-0.8.0-mint1-cinnamon-amd64.iso` к новой VM, не части `.partNN`.

### Linux

Скачайте части, `ASSEMBLY.json` и `assemble.sh` в одну папку. Выполните `bash assemble.sh` (нужен Python 3). Скрипт проверяет части и итоговый хеш. Итоговый хеш также в `ISO-SHA256SUMS.txt`; `SHA256SUMS` проверяет распространяемые файлы.

Если итоговый ISO окажется меньше лимита, он публикуется целиком; смотрите `DOWNLOAD.txt` в конкретном релизе.

## Первый тест

- Новая VM, 2 CPU, 4–6 ГБ RAM, **пустой виртуальный диск от 30 ГБ**.
- Secure Boot выключен: работа производного образа с ним не заявлена.
- Live-учётная запись и вход оставлены штатными Mint; прежний `tester/live` больше не используется. Обычно Live Mint входит автоматически.
- Выберите русский язык в штатном установщике. Создайте собственного пользователя с новым паролем.
- Установка может удалить данные. Сначала только отдельная VM, резервные копии обязательны.
- После установки отключите ISO и проверьте загрузку, сеть, звук, обновления, оформление.
- Live без persistence не сохраняет изменения после перезагрузки.

Запишите время первого и повторного открытия файлового менеджера, терминала и настроек в Hyper-V. По возможности сравните с **оригинальным Mint 22.3 Cinnamon** при тех же ресурсах VM. Новая база и Zstandard вместо XZ **не доказывают**, что прежняя задержка исправлена.

## Как собирается

`scripts/build.sh` скачивает официальный ISO с зеркала в `mint/source.json`, импортирует ключ с **закреплённым fingerprint**, проверяет подпись `sha256sum.txt.gpg`, затем SHA256 исходного ISO **до распаковки**. После этого добавляет только `mint/overlay`, компилирует отдельную dconf-базу без блокировок и пересобирает squashfs с Zstandard.

Xorriso переиспользует исходное гибридное BIOS/UEFI-загрузочное оборудование (`-boot_image any replay`), исходные boot-конфиги и EFI-раздел. Обновляются `filesystem.size` и соответствующие записи `md5sum.txt`. Подпись Mint удостоверяет **только исходный** ISO, не производный EroDist. Наш образ имеет отдельную контрольную сумму; своей криптографической подписи релиза пока нет.

Сборка в GitHub Actions на Ubuntu 24.04. Локально нужны root, `xorriso`, `squashfs-tools`, `dconf-cli`, `gnupg`, `curl`, Python 3, сеть к зеркалу/серверу ключей и примерно 25 ГБ свободного места:

```sh
sudo bash scripts/build.sh
```

Нужен чистый каталог `build/mint` перед повторной сборкой. ISO, rootfs и части находятся только в игнорируемых `build/` и `artifacts/`, не в Git. Проверки: `python3 -m unittest discover -s tests -v`.

Сборка проверяет подпись/хеш исходника, наличие Cinnamon и Mint metadata, сохранение загрузочных записей и целостность файлов релиза. **Это не заменяет тест BIOS/UEFI, установки, PowerShell-сборки на реальной Windows и запуска приложений в Hyper-V.** Условия лицензий пакетов и товарные знаки Linux Mint сохраняются; сборка обозначена как производная.
